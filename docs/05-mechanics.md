# 05 · 核心机制规则（源真相）

这里定义所有产品规则的精确语义。server / jobs / web 都必须以此为准，分歧时以本文档 + `packages/shared` 的实现为准。

## 1. 打卡日与日切边界

- 一个「打卡日」从**每日 05:00（打卡设备的当地时区）**开始，到次日 04:59 结束。
- 即：凌晨 04:30 打卡仍归「昨晚」，05:30 起算「今天」。
- **跨时区**：时区以「打卡那一刻设备所在地」为准，不绑人、不绑群（旅行自适应）。
- 实现用 `shared/day.currentCheckinDay(tz, now, boundaryHour=5)`，`tz` 取打卡时前端上报的 IANA 时区。

## 2. 一夜的三种结果（classifyNight）

| 结果 | 判定 | 含义 |
|---|---|---|
| `early` | 有打卡，且墙上时钟 ≤ 个人 `targetBedtime` | 早睡 |
| `late` | 有打卡，且墙上时钟 > `targetBedtime` | 晚睡 |
| `missing` | 无打卡记录 | 无记录 |

- `targetBedtime` 是**每人自己设**的目标（默认 `23:00`），不是群统一时间。
- 判定用 `shared/sleep.classifyNight`。
- **目标就寝时间是「本地时间锚点」**：跟着人走，跨时区/旅行不变；判定时区用打卡记录自带的 `timezone`。
- **凌晨（0 点至 5 点日切边界）打卡 → 一律 `late`**（熬夜，不算早睡）。

## 3. 打卡（check-in）

- **输入**：`POST /api/v1/checkin`，记录服务端当前时刻（`checkedInAt = now`）。
- **幂等**：`UNIQUE(member_id, date)`，同一天重复打卡 = 更新 `checkedInAt`（允许在日切前修正）。
- **即时回执**（server 返回 + 可选 ntfy 回执）：
  - early → `earlyCheckinMessage`：庆祝（可附「比目标早 X 分钟」）
  - late → `lateCheckinMessage`：温和提醒「比目标晚了约 X 分钟，明天提前一点点」，**不羞辱**
- **晚睡分钟数跨午夜**：用 `shared/sleep.minutesLate` 计算；墙钟早于目标（熬夜到次日凌晨）时加 24h，
  如目标 23:00、凌晨 00:36 → 晚 96 分钟（而不是 0）。

## 4. 可见统计（日常只展示这些）

- **累计早睡天数**（`early` 总数）
- **早睡占比** = early / (early + late)，只在**有记录的夜晚**里算，`missing` 不进分母也不进分子
- **绝不展示 streak**、绝不做「连续 X 天」的进度条或倒计时

## 5. 隐藏连续奖励（核心反作弊机制）

**背景**：因为「无记录不惩罚」，存在「晚睡就不打卡」的作弊动机。对策：连续早睡是**隐藏**的奖励。

规则：

1. **隐藏连续早睡** = 连续 `early` 的夜晚数（`computeStreak` 只喂「早睡日期」）。
   - 一个 `late` 之夜 → 断
   - 一个 `missing` 之夜（无论忘记还是故意跳过）→ **同样断**
2. 之所以「missing 也断」：若 missing 不断，作弊者就能「晚睡不打卡」而不影响连续，奖励就失去了反作弊作用。
3. 因为它是**隐藏**的：断了不提示、不展示、不算惩罚；只在达标时以惊喜奖牌揭示。诚实但偶尔忘打卡的人，代价只是「某天奖牌没来」，不会体验成惩罚。
4. **里程碑**：连续早睡达到 `7 / 21 / 30 / 66 / 100`（`shared/rewards.HIDDEN_STREAK_MILESTONES`）→ 触发惊喜奖牌。
5. **周期奖励**（Phase 2+）：某自然月**每一晚**都是 `early`（「整月全勤早睡」）也可触发。
6. **揭示方式**：晨报结算时（次日 05:00 后）检测昨晚是否跨过里程碑 → `rewardMessage` 推送 + 打卡页惊喜卡。奖牌在组内**公开可见**（唯一的社会信号，奖励诚实者）。

## 6. 睡前思考题（prompts）

- **触发**：已打卡者再次打开页面（睡不着），可领一道题。
- **性质**：闭眼可思考、低唤醒、可随时中断；**无判题、无对错、无计时**。睡着了 = 成功。
- 实现：`packages/prompts.createPromptSource().randomPrompt()`。不落库、无状态（至多会话级「今晚已领」）。

## 7. 晨报（次日 08:00，ntfy）

内容（按此顺序，基调=正反馈）：

1. 昨晚谁早睡（庆祝）
2. 谁晚睡（温和提醒，不点名羞辱）
3. 隐藏奖励揭示（若有达标）
4. 进步：与自己上周平均就寝时间比（「比上周平均早 X 分钟」）
5. 一句中性统计：昨晚 N 人记录、M 人未记录（**不点名**未记录者）

## 8. 月报 / 年报

- 早睡占比、累计早睡天数、平均就寝时间、就寝时间趋势线
- 晚睡次数与分布（**体现**，这正是「晚睡要进入统计」的落点）
- 无记录夜晚：中性呈现（「本月有 X 晚未记录」），不计入早/晚占比
- 年报额外：全年奖牌回顾

## 9. 明确不做

- ❌ 补卡 / 免死金牌 / 断签恢复任务（已被「无惩罚」模型取代）
- ❌ 对「忘记打卡」的任何提示或统计
- ❌ 防作弊工程（禁粘贴/防 LLM）：朋友间无利益，靠隐藏奖励 + 社会可见性即可

## 10. 身份与打卡链接

- **身份 = 打卡链接**：`join` 时用「昵称 + 口令」注册，服务端返回一条稳定链接 `BASE_URL/c/<token>`，持有即本人（可收藏、跨设备）。
- token 由 `deriveLinkToken(groupId, nickname, password)` 确定性派生，稳定不变；服务端只存 sha256，不存明文。
- **找回 = 登录**：同名+同口令再次调用 `join` 返回同一条链接；口令只存加盐哈希。

## 11. 原始事件流（events）

- 服务端记录「打卡后再次访问」（`visit_after_checkin`）等开放类型事件，追加不覆盖、不去重。
- 目的：保留最有意义的原始数据，供后续迭代（失眠判定、`做题大王` 等称号、周报/月报）使用。

## 12. 早睡榜状态（打卡墙）

起床时间 = 打卡时间 + `SLEEP_DURATION_HOURS`（默认 8h）；夜间窗口 = 20:00 至次日 05:00（各成员当地时区）。

| 状态 | 条件 | 显示 |
|---|---|---|
| `sleeping`（已打卡） | 正在睡（打卡后 8h 内）且打卡在夜间 | `22:45 · 纽约 · 3小时前` |
| `reversed`（白日做梦） | 正在睡但打卡在白天 | `白日做梦 · 10:00` |
| `not-slept`（还没睡） | 未在睡且当前夜间 | `还没睡` |
| `awake`（醒着） | 未在睡且当前白天 | `醒着` |
